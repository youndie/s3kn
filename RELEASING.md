# Выпуск

## Что публикуется

Три модуля: `s3-core`, `s3-sigv4`, `s3-client`. Координаты — `io.github.youndie:<модуль>`,
таргеты `jvm`, `linuxX64`, `macosArm64`.

`s3-testing` **не публикуется**, и это не забывчивость. Его загрузчики находят векторы по
абсолютному пути, вшитому в сборке (см. `s3-testing/build.gradle.kts`), так что вне этого
репозитория они указывают на несуществующий каталог. Артефакт, работающий только на машине, где
его собрали, хуже отсутствующего.

## Снапшоты

Уезжают в Reposilite (`https://reposilite.kotlin.website/snapshots`) — кнопкой
**Publish snapshot** в Actions. Кнопка, а не автоматика: снапшот, появившийся оттого, что кто-то
что-то запушил, — это снапшот с неизвестным происхождением.

Креды берутся из секретов репозитория:

| Секрет | Что это |
|---|---|
| `REPOSILITE_USER` | пользователь Reposilite |
| `REPOSILITE_SECRET` | его токен |

Подпись не нужна: её требует Maven Central, а снапшот-репозиторий — нет, и держать GPG-ключ в CI
ради снапшота незачем.

Задание одно, а не два. В соседнем kmp-smtp-client их два, потому что cinterop требует заголовков
целевой платформы и половину артефактов приходится собирать с macOS. Здесь cinterop нет вовсе —
TLS приезжает готовым внутри klib'а движка (ресёрч, факты 1.1 и 1.2), — поэтому Linux-раннер
кросс-компилирует все klib, включая `macosArm64`. Это то самое решение из ресёрча, окупившееся
на выпуске.

Перед публикацией CI прогоняет полную сборку с живым MinIO: снапшот — это всё равно то, на что
кто-то будет ссылаться.

## Подключение у потребителя

Репозиторий читается **без учётных данных** — креды нужны только на запись.

```kotlin
repositories {
    maven("https://reposilite.kotlin.website/snapshots")
}

dependencies {
    implementation("io.github.youndie:s3-client:0.1.0-SNAPSHOT")
    // На Kotlin/Native — единственный движок, который умеет HTTPS.
    implementation("io.ktor:ktor-client-curl:3.5.2")
}
```

## Проверка перед публикацией

```bash
./gradlew publishToMavenLocal
```

Посмотреть, что в `~/.m2/repository/io/github/youndie/` лежит двенадцать каталогов — по одному
общему и по три платформенных на каждый из трёх модулей, — и что `s3-testing` среди них нет.

После публикации то же самое проверяется снаружи, и это не то же самое, что «Gradle отрапортовал
успех»: собрать пустой проект, подключить снапшот и запустить. Один раз так и было сделано —
`linuxX64`-бинарь, собранный против опубликованных артефактов, напечатал presign-ссылку.

## Релиз в Maven Central

Пока не делается. Версия остаётся `-SNAPSHOT`, публикация идёт только в Reposilite. Для Central
понадобятся подпись, javadoc-артефакты и проверка namespace — отдельная задача, которую имеет смысл
брать, когда API устоится.
