# s3-core

## 1. Зона ответственности

Всё, что нужно знать о запросе **до** того, как его кто-то подпишет или отправит: адресация,
кодирование ключа, метка времени, учётные данные, модель ошибки.

Чем не занимается: не подписывает (это `:s3-sigv4`), не отправляет (это `:s3-client`), не знает
про Ktor и про сеть вообще. Зависимостей нет ни одной — модуль состоит из чистых функций и
значений.

Главный инвариант: **строка, которую подписывают, и строка, которую отправляют, приходят отсюда
одна и та же.** Всё остальное в модуле подчинено этому.

## 2. Контракт

Разделы 1–2 из [protocol-s3.md](../api/protocol-s3.md): адресация и кодирование ключа.

## 2а. Ключевые файлы (якоря кода)

| Файл | Что там |
|---|---|
| `UriEncoding.kt` | `uriEncodeKey`, `uriEncodeQueryComponent`, `uriDecode` — единственный кодировщик и его обратная сторона |
| `CanonicalQuery.kt` | третья строка canonical request, она же query на проводе |
| `SigningTimestamp.kt` | `yyyyMMdd'T'HHmmss'Z'` и `civil_from_days`; календаря в stdlib нет |
| `S3Endpoint.kt` | разбор endpoint, вывод `host` с правилом про дефолтный порт |
| `S3Config.kt` | стиль адресации, построение пути и URL, `allowUnsignedPayloadOverHttp` |
| `S3Exception.kt` | ошибка с кодом S3 **или** без него; `S3ErrorCode` — константы |

## 3. Как устроено

**Один кодировщик, а не два.** `uriEncodeKey` зовут и подписывальщик, и построитель URL. Два
кодировщика, различающиеся одним символом, дают `SignatureDoesNotMatch`, и ответ сервера не
называет ни символа, ни поля (ресёрч, Р4).

**Метка времени — тип, а не строка.** `SigningTimestamp.scopeDate` это `amzDate.substring(0, 8)`.
Отдельно вычисленная дата верна 86 399 секунд в сутки; на последней запрос отвергается без
объяснений.

**`+` читается двумя способами.** В пути и в query — по RFC 3986, где `+` ничего не значит.
В ответе листинга — по-формному, где `+` это пробел. Отсюда параметр `plusIsSpace`; подробности —
[protocol-s3.md, раздел 4.5](../api/protocol-s3.md).

## 4. Зависимости

Нет. Ни одной внешней библиотеки — это условие того, что модуль собирается на всех таргетах KMP.

## 5. Quirks

- **`S3Credentials` намеренно не `data class`.** Сгенерированный `toString` положил бы секретный
  ключ в каждую строчку лога, где печатается конфиг.
- **Порт сравнивается с дефолтом своей схемы, а не с числом.** 443 — дефолт для https и обычный
  порт для http; `http://example.com:443` обязан сохранить порт в `host`.
- **`encodedPathFor` с пустым ключом в path-style даёт `/bucket/`** — с завершающим слэшем.
  Одно правило на оба случая лучше двух похожих.
