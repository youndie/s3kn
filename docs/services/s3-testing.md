# s3-testing

## 1. Зона ответственности

Доступ к тому, что лежит в [`docs/spec/`](../spec/): 34 официальных вектора SigV4, 20
сгенерированных из botocore, таблица кодирования ключей. Плюс чтение переменных окружения, которыми
включаются тесты, требующие сервера.

Чем не занимается: ничего не проверяет сам. Это фикстуры, а не тесты.

**Не публикуется.** Путь к векторам вшивается в сборке (см. раздел 3), так что вне этого
репозитория загрузчики указывают на несуществующий каталог. Подробности — [RELEASING.md](../../RELEASING.md).

## 2а. Ключевые файлы (якоря кода)

| Файл | Что там |
|---|---|
| `SigV4TestSuite.kt` | загрузчик официальных векторов; `sessionToken` читается из `.creq` |
| `ParsedHttpRequest.kt` | разбор сырого HTTP-запроса из `.req` |
| `S3SigningVectors.kt` | загрузчик векторов, сгенерированных из botocore |
| `Environment.kt` | `S3_E2E_*`; `endpointOrSkip` |
| `build.gradle.kts` | задача `generateSpecPath` |

## 3. Как устроено

**Понятия «ресурсы теста» в KMP нет.** На Kotlin/Native нет classpath, а векторы обязаны остаться
байт в байт такими, какими их опубликовал AWS, — копия в `resources` означала бы вторую копию
эталона. Поэтому задача `generateSpecPath` записывает абсолютный путь `docs/spec` в сгенерированную
константу, а файлы читаются через `kotlinx-io`.

**Парсер `.req` намеренно не общего назначения.** Общий — это ровно то, из-за чего SDK пропускают
четыре кейса из 34: путь запроса может содержать пробел, а query — повторяющиеся имена.

**Токен сессии читается из ожидаемого выхода.** Циклично, и другого источника нет: два кейса с
токеном несут разные токены, а третий — креды без токена вовсе, и видно это только в `.creq`. Так
же поступает штатный прогон botocore.

## 4. Зависимости

| Тип | Имя | Для чего |
|---|---|---|
| Библиотека | `kotlinx-io-core` | единственный файловый API, работающий на всех таргетах |

## 5. Quirks

- **Файлы векторов кончаются без перевода строки** и разделяются `\n`, даже `.req`, который
  является HTTP-запросом. `.editorconfig` и `.gitattributes` ограждают `docs/spec/` от всего,
  что трогает байты.
- **`S3_E2E_REQUIRED=1` превращает отсутствие сервера в падение.** Без этого пропущенный тест
  читается точно так же, как прошедший.
