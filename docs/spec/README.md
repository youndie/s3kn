# Спецификация в репозитории

У S3 нет RFC. То, что здесь лежит, — три ближайших к спецификации артефакта, которые можно
положить в репозиторий и читать без сети. Ссылка на строку отсюда обязательна в каждом тесте
(правило Р10 ресёрча).

Прозаическая документация AWS (`docs.aws.amazon.com/AmazonS3/latest/API/…`) сюда **не копируется**:
она отдаётся JavaScript'ом, текстовой версии для скачивания нет, и лицензии на редистрибуцию тоже
нет. На неё ссылаемся URL'ами.

## Что лежит

### `aws-sig-v4-test-suite/` — официальные векторы подписи

34 кейса, по пять файлов на кейс:

| Файл | Что в нём |
|---|---|
| `<case>.req` | сырой HTTP-запрос — вход |
| `<case>.creq` | ожидаемый canonical request |
| `<case>.sts` | ожидаемый string to sign |
| `<case>.authz` | ожидаемый заголовок `Authorization` |
| `<case>.sreq` | тот же запрос с подставленным заголовком |

Входные данные фиксированы для всех кейсов:

```
access key  AKIDEXAMPLE
secret key  wJalrXUtnFEMI/K7MDENG+bPxRfiCYEXAMPLEKEY
timestamp   20150830T123600Z
region      us-east-1
service     service
```

**Важно про `normalize-path/`.** Восемь кейсов из 34 проверяют нормализацию пути (`/./` → `/`,
`/example space/` → `/example%20space/`). Это поведение **общего** SigV4; S3 путь не нормализует
и не перекодирует (`reference/botocore-auth.py:538`). В S3-режиме эти кейсы обязаны давать другой
ответ — см. ресёрч, следствие 1.4.2.

Источник: `boto/botocore`, `tests/unit/auth/aws4_testsuite`. Лицензия — Apache 2.0, файлы
`LICENSE` и `NOTICE` лежат рядом и удалению не подлежат.

### `s3-signing-vectors/` — векторы для того, чего AWS не публикует

Официальный набор покрывает **общий** SigV4. Двух вещей в нём нет вовсе: правила S3 «путь
подписывается как есть» и presign. Эти векторы закрывают пробел — их выдал botocore, тот самый код,
которым подписывает `aws-cli`.

| Что | Где |
|---|---|
| 13 кейсов подписи заголовками | `header/<case>/` — `input`, `creq`, `sts`, `authz`, `sha256` |
| 7 presign-ссылок | `presign/<case>/` — `input`, `url` |
| Кодирование ключей питоновским `quote` | `key-encoding` |
| Версия botocore, которой сгенерировано | `generated-with.txt` |

Генератор — [`generate.py`](s3-signing-vectors/generate.py), лежит рядом и перегенерирует всё
на месте:

```bash
cd docs/spec/s3-signing-vectors
python3 -m venv .venv && .venv/bin/pip install botocore
.venv/bin/python generate.py
```

**Это не официальные векторы**, и они настолько же надёжны, насколько надёжна эталонная
реализация. Ценность их в другом: botocore — независимая реализация, а не пересказ поведения этой
библиотеки, поэтому совпадение с ним что-то значит. Файл `key-encoding` в этом смысле самый
полезный: ожидания в нём выданы питоновским `quote`, то есть совпадение с ним проверяет наше
прочтение правила, а не только его повторение.

### `s3-service-2.json` — машинная модель API S3

`botocore/data/s3/2006-03-01/service-2.json`, протокол `rest-xml`. Отвечает на вопросы «какой
метод и URI у операции», «как называется query-параметр», «приезжает поле заголовком или в теле»,
«какой код успеха». Это единственный источник, где такие вещи записаны формально, а не прозой.

Точки входа по строкам:

| Операция | Строка |
|---|---|
| `AbortMultipartUpload` | `:18` |
| `CompleteMultipartUpload` | `:32` |
| `CreateMultipartUpload` | `:108` |
| `DeleteObject` | `:329` |
| `GetObject` | `:717` |
| `HeadObject` | `:878` |
| `ListObjectsV2` | `:1014` |
| `PutObject` | `:1353` |
| `UploadPart` | `:1596` |

Формы данных — в `shapes` того же файла: `ListObjectsV2Request`, `ListObjectsV2Output`,
`UploadPartOutput`, `CompleteMultipartUploadRequest` и так далее. На них ссылаемся путём внутри
JSON (`shapes.UploadPartOutput.members.ETag`), а не номером строки: строки в `shapes` едут при
каждом обновлении модели.

### `reference/botocore-auth.py` — эталонная реализация подписи

`botocore/auth.py` — код, которым подписывает запросы `aws-cli`. Когда документация AWS
и поведение расходятся, прав этот файл. Лицензия — Apache 2.0, шапка сохранена.

Полезные строки:

| Что | Строка |
|---|---|
| хеш пустого тела | `:55` |
| формат метки времени | `:63` |
| чёрный список неподписываемых заголовков | `:64` |
| вывод `host` из URL | `:81` |
| кодирование и сортировка canonical query | `:268` |
| выбор хеша тела, включая `UNSIGNED-PAYLOAD` | `:334` |
| сборка canonical request | `:370` |
| нормализация пути в **общем** SigV4 | `:385` |
| string to sign | `:405` |
| вывод ключа подписи | `:417` |
| **S3 путь не нормализует** | `:538` |
| S3 не подписывает тело на потоках поверх https | `:497` |
| presign: набор query-параметров | `:722` |
| presign: подпись дописывается последней | `:787` |
| presign: тело всегда `UNSIGNED-PAYLOAD` | `:810` |

## Как обновлять

Все три артефакта — снимки, а не подписки. Обновляются руками и **отдельным коммитом**, потому что
после обновления номера строк в ссылках из тестов и документов разъезжаются.

```bash
curl -sL -o docs/spec/s3-service-2.json \
  https://raw.githubusercontent.com/boto/botocore/develop/botocore/data/s3/2006-03-01/service-2.json
curl -sL -o docs/spec/reference/botocore-auth.py \
  https://raw.githubusercontent.com/boto/botocore/develop/botocore/auth.py
```

После обновления — прогнать тесты и перепроверить таблицы строк в этом файле.

Набор векторов подписи трогать не нужно вовсе: он привязан к алгоритму, а не к сервису, и его
`NOTICE` датирован 2019 годом.
