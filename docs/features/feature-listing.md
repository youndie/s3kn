# Перечисление содержимого бакета

## 1. Суть

Пройти по ключам бакета — целиком, по префиксу или «по каталогам», когда задан разделитель.
Выдача идёт страницами и лениво: бакет на миллион ключей не приезжает в память, чтобы ответить на
вопрос о первой сотне.

## 2. Бизнес-ограничения

- `encoding-type=url` отправляется **всегда**. Ключ может содержать символ, который XML 1.0 не
  представляет вовсе, и без этого ломается сам документ.
- Ответ листинга декодируется **по-формному**: пробел в ключе приезжает как `+`. Литеральный `+`
  приезжает как `%2B`, поэтому неоднозначности нет.
- Токен продолжения **не декодируется**: он непрозрачный и уезжает обратно дословно.
- `KeyCount` — число ключей на странице, не в бакете.
- `CommonPrefixes` — отдельная ветка результата. Это не объекты, и запрашивать их как ключи нельзя.

## 4. Якоря кода

| Модуль | Код |
|---|---|
| `:s3-client` | `ListBucketResult.kt` — типы и разбор |
| `:s3-client` | `S3Client.kt`, `listPage` и `list` |

## 5. Сценарии

| Сценарий | Ожидание | Где проверено |
|---|---|---|
| Перечислить по префиксу | ключи в лексикографическом порядке, `keyCount` = числу на странице | `S3ClientE2eTest`, `lists what it stored under a prefix` |
| Перечислить с разделителем | вложенное свёрнуто в `commonPrefixes`, верхний уровень — в `objects` | `S3ClientE2eTest`, `rolls keys up into common prefixes when given a delimiter` |
| Листинг не помещается на страницу | все ключи приходят, страницами | `S3ClientE2eTest`, `walks a listing that does not fit in one page` |
| Ключ с `<`, `>`, `&`, `"`, кириллицей, эмодзи | возвращается целым | `S3ClientE2eTest`, `lists a key whose name XML alone could not carry` |
| Коллектор остановился на первой странице | второй запрос не уходит | `S3ListRequestTest`, `stops requesting pages when the collector stops asking` |
